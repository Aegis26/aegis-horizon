World-Class CRM — Phased Agent Prompts
Product: Multi-tenant, feature-customizable CRM SaaS (37 features across 6 phases) Platform: Replit (React 18 + Vite + TypeScript, Express + TypeScript, PostgreSQL + Drizzle) Pricing Model: Pre-made tiers (Essential/Professional/Enterprise) + à la carte features with real-time pricing UI
Phase 1 — Foundation & Authentication (Weeks 1–3)
Goal: Deploy a multi-tenant platform with role-based access control, feature entitlements, and Stripe billing integration. No business features yet.
Deliverables: Auth system (Clerk), org/user/permissions schema, feature flag middleware, Stripe checkout flow, React shell with sidebar navigation, settings pages.
Acceptance Criteria:
New user signs up, creates org, selects a plan (Essential/Professional/Enterprise visible).
Can invite team members and assign roles (Owner, Admin, Manager, User, Viewer).
Feature gates enforce permissions server-side (hitting /api/opportunities without 'sales' feature returns 403).
Stripe checkout generates without errors; webhook updates org stripeCustomerId and subscription.
React app boots, Clerk auth works, logged-in user lands on org dashboard.
All migrations run cleanly, database ready for Phases 2–6.

Core API Routes
Auth (public)
POST /api/auth/signup — Clerk webhook + create user + create default org
POST /api/auth/login — Session-based (no OAuth needed)
POST /api/auth/logout
GET /api/auth/me — Current user + all orgs they belong to
Orgs
GET /api/orgs/:orgId — Org details (requires membership)
PATCH /api/orgs/:orgId — Update plan, name (requires owner/admin)
POST /api/orgs/:orgId/users — Invite user (requires admin)
DELETE /api/orgs/:orgId/users/:userId — Remove user (requires admin)
GET /api/orgs/:orgId/billing/checkout — Stripe session (requires owner/admin)
Billing
POST /api/webhooks/stripe — Validate Stripe signature, update org subscription on checkout.session.completed
Feature Gates (all return 403 if feature not enabled)
GET /api/accounts — requires 'crm' feature
GET /api/opportunities — requires 'sales' feature
GET /api/workflows — requires 'automation' feature
All other Phase 2+ routes follow the same pattern
Middleware & Auth
Create /src/middleware/auth.ts:
attachUser() — Extract Clerk JWT, fetch user from DB, attach to req.user
attachOrg() — Extract org_id from query or header, verify membership, attach to req.org
requireFeature(featureKey) — Check req.org.enabledFeatures includes featureKey, return 403 if not
All routes use: app.get('/api/...', attachUser, attachOrg, requireFeature('feature_name'), handler)
Stripe Integration
Create /src/services/stripe.ts:
FEATURE_PRICES object mapping feature key to price in cents
PLAN_FEATURES mapping each tier to included features
createCheckoutSession(orgId, features[], seatCount, plan) — Generate Stripe session
Webhook handler validates Stripe signature, updates org.stripeCustomerId and stripeSubscriptionId
React Billing Selector
Create <FeatureSelector /> component:
Tab between Essential / Professional / Enterprise / Custom
Custom shows grid of all features with checkboxes
Real-time price calculation as user checks/unchecks
Price display in both monthly and annual (20% discount for annual)
"Subscribe Now" button opens Stripe checkout with selected features
React App Shell
Create /client/src/App.tsx:
Left sidebar (desktop) or bottom tab bar (mobile)
Nav items: Dashboard, Accounts (requires 'crm'), Opportunities (requires 'sales'), etc.
Settings page with org name, team management, billing
All routes server-side gated; frontend just hides nav links
Critical Decisions
All timestamps are UTC in database, render in user's timezone (or default to America/Chicago for now).
Feature keys are the single source of truth for permissions. Every route checks requireFeature() at middleware level. Frontend hiding links is not access control.
Org invite flow: Generate one-time token, email link (via Resend), user clicks and sets password. No OAuth at signup.
Clerk is auth provider, not permission provider. Clerk handles login; your DB holds org membership and roles.
